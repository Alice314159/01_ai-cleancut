# AI CleanCut 前端工程

对应《AI CleanCut Baseline V2.1》。四个页面覆盖三条主路径：录制 → 增强 → 复核，外加会话列表。
电脑端与手机端是同一套组件，不做两份实现。

## 运行

```bash
npm install
npm run dev        # 开发，默认 http://localhost:5173
npm run build      # 产出 dist/index.html（静态资源内联）
npm run typecheck  # 只做类型检查
```

`npm run build` 将 JS 与 CSS 内联到 HTML，但实际业务仍请求后端 REST/WebSocket。
请通过本机开发服务器或已配置 CORS 的 HTTP 来源访问，录音需要麦克风权限。

## 响应式：为什么用容器查询而不是媒体查询

断点写在 `@container app (max-width: ...)` 上，`.app-root` 是容器。
好处是把根容器宽度设成 402px，移动端形态就**真的**生效了——评审时不用开 DevTools，
也不用维护第二套布局。右下角的「电脑端 / 手机端」开关就是靠这个实现的。

接入真实产品时删掉 `App.tsx` 里的 `viewport-host` 包装和 `.previewbar` 样式即可，
断点行为不受影响。

## 设计约定

交互主色为柔和紫色（`--primary`），用于主按钮、导航激活和选区；辅助色 `--accent` 用于时间戳。状态色保持独立语义：

| 令牌 | 含义 |
| --- | --- |
| `--sig-committed` 青 | 已确认转写 / 已判定决策 |
| `--sig-provisional` 琥珀 | 待定转写 / 实时提示 |
| `--sig-protect` 靛 | 保护区间，不可自动删除 |
| `--sig-cut` 绛 | 删除区间 |
| `--sig-danger` 橙红 | 严重警告：削波、设备断开 |

等宽字体只用于必须对齐的数据：时间码、样本数、评分、dB 值、版本号、ID。
正文不用等宽——时间码跳字是这类工具最常见的低级瑕疵，等宽在这里是功能性选择。

## 与设计文档的对应关系

以下 ADR 为历史设计引用，仓库未附原始需求全文；设计目标不等于已实现能力。

| 界面元素 | 依据 |
| --- | --- |
| 时间基准条常驻不可关闭 | ADR-024 / ADR-052。基准被静默改错是最难发现的失败模式，不报错只剪错；"复核试听"和"渲染"曾各占一格但值一直相同（都读 `RENDER_SOURCE`），纯重复已合并成一格，版本相同且无异常时不再额外展示"同版本"文案 |
| 波形带上排提示 / 下排判定 | ADR-053。已区分提示与判定的展示；实时语义信号和全量语义去重尚未实现 |
| 待定区间斜纹压暗 | ADR-047。该样式已保留；流式转写及后续窗口改写尚未实现 |
| 守卫提示两级且都非模态 | ADR-049。打断创作者比漏一次提示代价更大 |
| 输入设备卡显示"实际"而非"请求" | ADR-036。浏览器会静默忽略约束 |
| 增强页强调"不改变时间基准" | ADR-052。降噪只改成片音质，所以调强度不会让决策失效 |
| 人声保护指标而非只看噪声下降 | ADR-044。只看噪声下降会系统性奖励过度降噪 |
| 会话列表分阶段显示 | ADR-040。分别展示采集、服务端接收、合并校验、增强处理；"浏览器保存"曾单独占一列但每行都固定显示"未支持"，没有信息量，已删掉改在页头说明文字里统一交代一次 |
| 单条决策编辑冲突四选项 | 已实现采用最新、应用我的、改为待确认、暂不处理；原始 ADR-039 选项定义缺失，尚不能确认与其完全一致 |

## 当前流程与边界

四个页面已调用真实后端。增强页会等待停止后的质量报告，按当前 job ID 轮询，显示失败原因。录制页卸载会等待最后一个 MediaRecorder 分片后发送 stop；断线会停止麦克风并调用 HTTP 兜底。

会话页和无会话占位页都提供"导入音频"，选择已有音频/视频文件后创建 `capture_mode=batch` 会话并直接上传，跳过录制页，完成后落在增强页——成功或解码失败都在这里显示，和录制走同一套质量分析与失败文案。单个会话只能导入一次；会话列表按 `captureMode` 区分"在线录制"/"录后处理"，录后处理会话不会被路由到录制页。侧栏"01 录制"对任意会话始终可点——录后处理会话点进去不会显示用不上的实时录制界面，而是提示没有录制阶段并给一条直接进入复核页剪辑的出路。

已接入本机录后转写，支持自动识别、中文和英文，录制/导入终态化后自动排队，不需要先点"开始本机转写"（该按钮仍保留，用于切换语言重新识别或依赖未安装时重试）。中文转写统一转成简体——faster-whisper 的多语言模型对中文默认偏繁体输出，`language=auto` 和显式传 `zh` 都一样，不是识别错了语种，是模型出字的字形习惯，后端按检测到的语言转换。

点击转写词可试听并选中：第一次确定起点，第二次扩展范围，也可用鼠标、触控笔或触屏直接拖选；不再依赖 Shift。选好后点“删除选中文字”直接生成删除决策。词与词之间超过 400ms 的停顿会标成“‧‧‧0.8s”，同样可以选择删除。起止秒数保留在高级剪辑中。进度按任务 ID 轮询，失败保留已有文字。重复、口吃和语气词的实时语义识别尚未实现，随机实时提示已停用。复核页接受或拒绝已有候选后可生成真实成片、试听并下载 WAV。已生成但尚未确认的文字规则建议（重复/语气词）会直接在转写正文里用琥珀色虚线标出对应文字，不需要跳去决策列表核对是哪几个字；已接受的删除仍用删除线标出。

复核页的试听、手动区间和生成成片收在一条紧凑工具栏里；紧接着是"语音转写"（含选词/拖选/生成建议）和"剪辑决策"两栏——转写栏更宽、视觉在左，决策栏和"本次处理的提醒"在右，避免决策列表为空时和转写内容不对称造成的大片留白；波形图和"预计缩短/待人工确认/决策总数"统计卡放在这两栏之后，作为处理进度的汇总视图，不再挡在转写前面。顶部引导按钮会区分"转写完成但还没做任何标记"（引导去选词）和"待定项都已处理、可以渲染"（引导去生成成片）两种状态，不再共用同一句文案。选中文字后的"删除选中文字"操作条为 `position: sticky`，长转写滚动时仍贴在可视区底部。"预计缩短""待人工确认"统计卡按状态着色（绿色/琥珀色左边框），"决策总数"保持中性。右下角电脑端/手机端预览开关是 `position: fixed`，滚动区域底部留了对应高度的 padding，避免盖住最后几行内容。

验证：`npm run typecheck`、`npm run build`、`npm run test`（vitest，覆盖 `lib/format.ts` 和 `lib/api.ts` 的纯逻辑），以及后端目录下的 `python tests/browser_smoke.py`。浏览器脚本使用隔离存储，测试真实音频采集、上传、试听、多次增强、断线收尾、手动剪辑、成片播放和下载。

复核试听与渲染均读取 `RENDER_SOURCE`，顶部时间基准条展示相同音频源；`REVIEW_SOURCE` 不代表当前复核播放器所用版本。源发生变化后，已生成成片需重新生成。基准条不宣称完成独立的延迟或时钟漂移校验。

录后可手动生成相邻重复和独立语气词建议，逐条接受/拒绝或批量拒绝待定建议。支持 TXT 和 SRT 下载；字幕时间对应剪辑前录音。录制页和会话列表不再将当前功能称为“即录即剪”。

会话列表页头的"项目"输入框决定下一个新建/导入会话归到哪个项目，浏览器本地记住最近一次输入（`localStorage`，键 `cleancut.lastProjectId`），跨设备或清空存储后失效。搜索框按标题或会话 ID 过滤，项目下拉按 `projectId` 过滤，两者可叠加；行内的项目 chip 本身也是按钮，点一下等价于用下拉选中该项目。选中具体项目（非"全部项目"）时会出现"项目分析"卡片：会话数、总时长、平均时长，以及按处理状态分布的计数——全部由前端对已加载的会话列表现算，没有服务端聚合接口。

会话列表不再是固定列的 `<table>`——之前"浏览器保存"那一列每行都固定显示"未支持"，没有信息量，删掉后页头说明文字已经涵盖这个事实；改成跟"剪辑决策"同一种 grid 行卡片（`.session-row`），移动端自动收成单列，不再需要横向滚动才能看到"增强处理"状态。每行右侧的 ✎/🗑 分别重命名标题/改项目、删除会话；删除前有一次行内二次确认（不是浏览器原生 `confirm()`），确认文案会提示音频和剪辑决策一并清除、不可恢复。

## 交互主路径

主要操作路径调整为“录制／导入 → 转写与剪辑 → 试听导出”，降噪作为可选步骤。导入成功及重新打开已就绪会话直接进入复核页；录制结束提供“下一步：转写与剪辑”，增强页提供“继续剪辑”。

复核页顶部按当前状态显示下一步入口：开始转写、转写已完成但还没做任何标记时去选词剪辑、确认待定建议、准备生成成片或试听下载。入口跳转到对应操作区域，不会自动启动转写、接受删除或生成文件。手动按秒剪辑仍可直接使用，语言选择保留在转写区域。

复核工作区先展示“转写与选段”，再展示已有剪辑决策。未转写时隐藏建议查找和文字导出，避免出现一排不可用按钮；按秒输入收在“高级剪辑”中。无需文字处理时可直接选择“跳过转写，导出完整音频”。

转写成功后会自动生成相邻文字重复的待复核提示，与转写文字一起发布；复核页显示疑似重复数量并高亮对应文字。不会自动接受或删除，已接受／拒绝的选择保持不变。当前按相邻相同文字匹配（最多 12 个词单元，整组不超过 8 秒，词间间隔不超过 1 秒），不支持跨会话或改写后的语义重复识别。语气词仍通过“查找重复与语气词”手动查找。


## 剪辑中重录

选中文字后使用“重录选中片段”，高级剪辑支持按秒指定“重录此时间范围”，每条非保护决策也提供“重录这段”。弹窗固定本次替换范围，使用浏览器麦克风录音；停止后先试听，再“应用重录替换”。应用后加载最新决策并标记旧成片过期；新录音在决策卡内可单独试听、撤销或再次重录。手机与电脑使用同一弹窗，取消、关闭或离开时释放麦克风和预览 URL。

新片段长度不必等于原片段，成片统计区分净缩短／增加。应用会替代范围内已有剪辑；部分重叠或保护片段由服务端拒绝。并发冲突保留当前录音，可刷新剪辑选择后核对重试。原转写仍显示原始内容，已应用重录用青色标记；含重录的成片自动进行独立转写，显示进度、新文字及 TXT／SRT 下载入口；失败可重试。


## 视觉与复核布局

采用分层深色底面、浅灰正文与紫色交互高亮，侧栏独立背景。按钮分为高亮主操作、描边次要操作和文字链接；待定剪辑通过琥珀色横幅提示，并可直接跳转处理。

复核页在宽屏使用左侧转写、右侧试听与生成／高级剪辑／决策的两栏布局。右侧工具区随主区滚动保持可见，内容过多时可独立滚动；容器不超过 1180px 时恢复单栏顺序，手机端增加按钮触控高度并避让底部导航。转写增加字号和行距，停顿采用低对比标签，数字时间戳保留等宽字体。


录制记录页采用三层卡片：第一行文件名与编辑／删除操作，第二行 ID、项目、录制模式和时长，底部为采集、接收、校验、增强四阶段状态胶囊。文件名按钮打开会话，项目按钮仅切换筛选。工具栏左侧搜索与筛选、右侧新录制与导入；新建归属项目保留独立标注，长说明默认收起。窄屏状态胶囊排列为两列，操作按钮保持在标题右侧。


增强页将八项质量指标收纳为统一看板，桌面四列、手机两列；降噪强度使用分段选择，主按钮集中启动增强，进度和结果直接显示。人声保护与处理链默认折叠，警告始终展示。版本列表按“版本与用途／试听对比／音频信息”三列排列，以 RENDER_SOURCE 高亮当前剪辑源；手机改为版本卡片。播放器统一尺寸并加载时长元数据，同一列表只播放一个版本。引擎、延迟及可复现性保留在每版技术详情中。


复核工具区在容器宽度不超过 1180px 时采用抽屉，审核胶囊避让底部导航和预览开关。关闭时工具区 inert 且不可见；打开时禁用背景、约束 Tab 焦点，支持 Escape 关闭并恢复触发点焦点。待确认入口展开并定位首条待确认决策。转写依据明显停顿、句末和长度上限分段，词按钮采用无内边距的行内排版，保留词级选择、拖选与决策联动；说明收起到可展开帮助中。

## 安卓 App（Capacitor）

- `npm run build:app`：App 版网页（`VITE_APP=1`，输出 `dist-app/`）。首次打开选择“连接电脑”或“先看演示”，选择保存在 App 本机。
- `npx cap sync android`：把 `dist-app/` 同步进 `android/` 工程；`android/` 下运行 `./gradlew assembleDebug` 生成 APK（需要 JDK 21 与 Android SDK（compileSdk 36））。
- GitHub 上由 `.github/workflows/android-apk.yml` 自动完成上述步骤，产物在运行页面的 Artifacts。
- 页面来源为 `http://localhost`（`capacitor.config.json` 中 `androidScheme: http`），以便访问局域网内的 `http://` 后端，同时仍是安全上下文，可使用麦克风。
